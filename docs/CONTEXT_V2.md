# 长会话上下文 V2 设计

本文定义路线图 M1 的数据边界、事实优先级和兼容策略。实现入口为 `src-tauri/src/agent/context.rs`，数据库结构由 `063_conversation_context_v2.sql` 创建。

## 1. 设计目标

Context V2 解决三个问题：

1. 对话超过模型窗口后，压缩历史但不丢失任务状态和可验证事实。
2. 应用重启或 Run 恢复时，从持久化真源重建上下文，不依赖进程内变量。
3. 文件、Git、构建、测试、设备和外部状态发生变化时，使旧事实显式失效。

Context V2 是投影层，不取代消息、事件、Run、工具结果或工作区本身。

## 2. 现有数据映射

| 数据 | 当前真源 | Context V2 用法 |
|---|---|---|
| 用户与助手消息 | `messages` | 组装最近消息热窗口；用 `rowid` 记录摘要覆盖区间 |
| 会话事件 | `session_events` | 回放消息生命周期；用 `seq` 标记摘要事件游标 |
| 历史摘要 | `conversations.summary` | 兼容读取；新写入同时保存到 Context V2 状态 |
| 任务账本 | `conversations.ledger` | 无 Durable Run 时的兼容任务快照来源 |
| 时间旅行快照 | `conversation_snapshots` | 继续承担消息分支恢复锚点 |
| 任务运行 | `agent_runs`、`run_events` | 当前目标、状态、阶段、错误与恢复状态真源 |
| 执行步骤 | `execution_steps` | 已完成、待完成和阻塞步骤真源 |
| 验收条件 | `agent_runs.goal_contract_json` | 任务快照中的必需条件 |
| 工具结果 | `tool_runs`、`tool_execution_attempts` | 事实和产物的证据来源，不复制完整长输出 |
| 会话 Todo | `conversation_todos` | 后续任务快照的计划投影来源 |
| 项目记忆 | `project_memories` | 按项目检索；不无条件写入热上下文 |
| 工作区 | 文件系统与 Git | 每次关键执行前重新观察，Context 中只保存带来源的事实 |
| 鸿蒙设备 | HDC 与设备服务 | 使用有时效的环境事实，连接状态变化后立即失效 |

## 3. 四层上下文

### 热上下文

最近消息、当前用户指令、当前错误、待审批事项和本轮工具结果。热上下文实时组装，不额外复制到 Context V2 表。

### 任务上下文

由 `TaskSnapshotV2` 表示，内容包括：

- Durable Run ID、目标、状态和阶段；
- 目标契约中的必需验收条件；
- 已完成、待完成和阻塞步骤；
- 下一步、最近错误和更新时间。

### 项目上下文

由带来源的 `ContextFactV2` 和 `ContextArtifactRef` 表示，例如 Git HEAD、活跃分支、构建命令、模块关系、构建产物和设备信息。

### 历史归档

原始消息、事件、工具输出和旧事实版本继续保存在各自真源中。摘要只保存导航信息及覆盖游标，需要细节时按来源回溯。

## 4. 新增存储

### `conversation_context_state`

每个会话一行，保存当前 Context V2 版本、摘要及覆盖游标、任务快照、预算、事实摘要和失效 epoch。

### `conversation_context_facts`

保存结构化事实。每条事实必须包含：

- `fact_kind + fact_key` 稳定身份；
- JSON 值；
- `source_kind + source_ref` 来源；
- conversation/project/run 作用域；
- 可信度、版本、观察时间和失效原因。

同一事实值和来源重复观察时只更新时间；发生变化时旧版本标记失效，新版本递增，历史不会被覆盖。

### `conversation_context_artifacts`

保存文件、Diff、构建包、报告、截图、日志等产物引用。表内只保存 URI、digest、元数据和来源，不复制大型内容。

### `conversation_context_snapshots`

保存 Context 投影检查点，用于审计摘要演进和重启恢复。每个会话只保留最近 80 条；它与现有消息时间旅行快照职责不同。

## 5. 事实优先级

发生冲突时按以下顺序裁决：

1. 当前工作区、Git、进程、设备或外部 API 的最新读取结果。
2. 已提交的工具结构化结果和带 digest 的产物。
3. Durable Run、执行步骤、验收报告和事件日志。
4. 活跃且来源仍有效的 Context Fact。
5. 项目记忆和知识库命中。
6. 自然语言摘要。

低优先级内容不得覆盖高优先级事实。检测到冲突时，应使旧事实失效并记录原因，而不是静默修改摘要。

## 6. 预算策略

`ContextBudgetV2` 先为输出预留约八分之一窗口，再把输入预算分配为：

| 区域 | 输入预算比例 |
|---|---:|
| 系统规则 | 15% |
| 任务状态 | 12% |
| 项目事实 | 13% |
| 历史摘要/检索 | 15% |
| 最近消息热窗口 | 45% |

小窗口最低按 4096 token 计算，输出预留限制在 1024–16384 token。后续可根据模型、任务类型和真实使用指标动态调整。

## 7. 失效规则

以下事件必须触发相关事实失效或重新观察：

- 项目、worktree 或 Git 分支切换；
- HEAD、工作区状态或关键配置文件变化；
- SDK、Node、JDK、Hvigor、OHPM 环境变化；
- 设备连接、系统版本、权限或应用安装状态变化；
- 用户修改目标契约或取消任务；
- 外部工具返回与缓存事实冲突的结果。

失效操作递增 `invalidation_epoch`，前端和 Agent 可以据此判断上下文是否在当前轮次被纠偏。

## 8. 兼容与回退

- 找不到 Context V2 状态时，从 `conversations.summary` 和最新 Durable Run 重建。
- 没有 Durable Run 时，从 `conversations.ledger` 生成兼容任务快照。
- Context V2 读取或持久化失败不得阻断聊天主流程，旧上下文路径仍可受控回退。
- 迁移只新增表，不修改旧消息、摘要、事件和快照数据。
- 完成稳定迁移前，旧摘要与 Context V2 摘要采用双写，读取优先 V2。

## 9. M1 接入顺序

1. 将预算分配器和 Context V2 读取接入聊天请求组装。
2. 把结构化任务快照作为每轮固定上下文，不再只依赖自然语言账本。
3. 摘要生成后双写 Context V2，并记录精确消息/事件游标。
4. 从工具结果提取文件、Git、测试、构建和设备事实及产物引用。
5. 在 Workspace 展示分层预算、摘要游标、事实来源和失效次数。
6. 增加 100+ 轮、压缩、重启和事实冲突回归测试。
