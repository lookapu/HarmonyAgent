# 工具质量指标、SLO 与协议迁移

本文是 TC-19～TC-23 的指标口径和兼容性约定。所有指标都从本地 SQLite 的 Durable `tool_runs` 计算，不把内存日志或模型自然语言当作真源。

## 指标口径

统计窗口只包含 `ok / error / blocked / cancelled / interrupted` 终态调用。

| 指标 | 计算方式 | 说明 |
| --- | --- | --- |
| 工具成功率 | `ok / 终态调用` | 只表示调用执行成功，不表示目标完成 |
| 参数错误率 | `TOOL_ARGUMENT_INVALID / 终态调用` | schema 预检失败使用稳定错误码，不解析展示文案 |
| 超时率 | `TOOL_TIMEOUT / 终态调用` | 包含工具执行器报告的有界超时 |
| 重试率 | `retry_count > 0 / 终态调用` | `retry_count` 是单次逻辑调用内部的实际重试次数 |
| 平均取消延迟 | `cancel_observed_at - cancel_requested_at` | 仅统计有停止请求时间的 `cancelled` 调用 |
| 平均耗时 | `AVG(duration_ms)` | 含成功和失败终态，避免只看成功样本 |
| 成功调用贡献率 | `contributing / ok` | 贡献必须进入最终 `AcceptanceReport` 的证据集合 |
| 无效成功率 | `no_direct_acceptance_evidence / ok` | 调用成功但未直接证明任何最终验收条件 |
| 副作用重复率 | 同 Run、同幂等键的额外成功副作用 / 成功副作用 | 被幂等门禁阻止的尝试不算真实重复执行 |
| 错误工具选择率 | `out_of_capability_pack / 终态调用` | 工具不属于目标选择出的能力包，且不是公共控制工具 |

最终贡献在运行验收完成后统一回填。系统从验收证据标签提取 `evidence_digest`，把直接证明验收条件的调用标为 `contributing`；其他成功调用标为 `no_direct_acceptance_evidence`。这使面板可以明确区分“工具调用成功”和“目标得到推进”。

## SLO

默认策略新增三条工具质量上限：

- 副作用重复率 `≤ 0%`，越界产生 critical 告警。
- 错误工具选择率 `≤ 5%`，至少 5 次调用后评估。
- 无效成功率 `≤ 25%`，至少 5 次成功调用后评估。

窗口评估使用同一份 `ToolQualitySummary`，避免面板和告警各自维护公式。告警采用单个策略、单个错误码只保留一个 open 告警的去重规则。

## 可靠性比较维度

控制面提供以下同口径切片，每个切片展示调用数、成功率、验收贡献率和平均耗时：

1. 工具名。
2. 目标能力包。
3. 实际模型；子 Agent 优先使用自身 DAG 节点记录的模型。
4. 项目 ID。
5. 工具协议版本与生产者应用版本。

空的历史维度显示为 `unknown`，不会从统计窗口静默排除，因此升级前后的覆盖差异可见。

## 工具协议版本边界

迁移 `069_tool_quality_governance.sql` 新增 `tool_protocol_versions` 目录：

| Schema | 状态 | 最低读取版本 | 兼容规则 |
| --- | --- | --- | --- |
| V1 | legacy | V1 | 保留只读；不再产生新的 V1 记录 |
| V2 | current | V1 | V2 读取器兼容缺失字段；未知未来字段通过 `extensions` 原样保留 |

边界规则：

- 新写入固定使用 `protocol_version = 2`，并记录 `producer_version`。
- V1 历史行继续参与基础统计；依赖 V2 结构化证据的功能必须显式检查字段存在。
- V2 增加字段只能使用可选字段或安全默认值，不允许修改既有字段语义。
- 如果未来版本无法由 V2 读取器安全解释，必须新增 schema 版本、目录记录和显式迁移，不能静默复用 V2。
- `evidence_digest` 不包含机器耗时，避免相同行为因硬件速度不同而失去证据身份。

## 验收

- Rust 测试验证各比率、取消延迟、最终贡献回填、能力包外选择和迁移完整性。
- 前端测试、lint 与生产构建验证控制面类型和渲染路径。
- 完整 Rust 回归继续覆盖工具崩溃、租约 fencing 和副作用防重放。
