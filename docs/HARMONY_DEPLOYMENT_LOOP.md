# HarmonyOS 设备部署闭环

`deploy`、`deploy_all`、`start_ability` 和 `uninstall_app` 共用 HM-13 的设备事实，不把“命令返回成功”直接等同于运行成功。

## 部署阶段

1. 从构建 manifest 安全选择并复验 HAP，或接受用户显式确认的签名 HAP。
2. 发现设备；即使调用方显式传入设备，也必须确认在线、已授权并具备 `install`、`ability`、`hilog` 能力。
3. 用 `bm dump` 记录部署前应用是否已经存在，再执行首次安装或 `-r` 覆盖安装。
4. 启动工程主 Ability，并在 8 秒窗口内三次读取 Ability 栈。只有持续观察到 bundle 才进入成功分支。
5. 成功后启动项目级 Hilog 监听；失败时先抓取 Hilog，启动后崩溃还会优先关联 faultlog 并写入跨轮诊断。
6. 若失败发生在本次首次安装之后，执行补偿卸载并再次查询确认；若部署前已存在应用，则保留覆盖后的安装，避免把用户原有应用一并误删。

上述阶段同时写入 Agent 的持久 Run 事件流；构建、设备、产物、日志和异常可按同一 `run_id` 与事件序号重放，字段契约见 [HARMONY_RUN_EVENTS.md](HARMONY_RUN_EVENTS.md)。

## 独立操作

- `start_ability` 在命令返回后最多观测三次 Ability 栈。显式 bundle 从未出现时，返回失败和相关 Hilog，而不是模糊的成功文本。
- `uninstall_app` 在卸载后用 `bm dump` 复验。仍能查到 bundle 时返回失败；确认卸载后停止该项目旧的运行日志监听。
- `deploy_all` 对显式和自动发现的设备执行相同门禁，去重后受控并行；每台设备独立安装、确认、取证和恢复。

## 安全边界

自动恢复只撤销当前部署明确创建的新安装。HarmonyAgent 不保存被覆盖设备包的旧二进制，因此覆盖安装后的失败不会伪装成已回滚，也不会自动卸载；输出会明确提示保留现状，交由后续诊断或用户确认处理。

## 验收

单元测试固定设备连接/授权/能力门禁和恢复范围不变量。阶段门禁包含全量 Rust 单元测试、两组 worker 崩溃恢复 E2E、前端测试、ESLint、生产构建与差异检查。
