A. 工具补全类（共 56 项）
================================================================

---------- A1. 工具元能力（LLM 自我发现）—— 3 项 ----------

[01] tool_list
    说明：动态列出当前可用工具（按域/任务分组）
    价值：system prompt 瘦身 + 模型自查询

[02] tool_help(name)
    说明：查某工具的详细参数 + 副作用 + 返回结构 + 示例
    价值：按需拉取，注意力更聚焦

[03] tool_history
    说明：查最近 N 次工具调用记录（带结果）
    价值：让 LLM 能"回看自己刚做了什么"


---------- A2. 编辑体验 —— 4 项 ----------

[04] preview_edit
    说明：edit_file 之前返回 diff 给用户确认（不落盘）
    价值：配合 pipeline 做"危险编辑审批"

[05] format_file
    说明：按 ArkTS 风格格式化单个文件
    价值：替代手动 run_lint

[06] snippet_insert
    说明：插入代码片段（自定义 snippet 库）
    价值：高频代码秒插

[07] code_metrics
    说明：圈复杂度 / 行数 / 注释率 / 嵌套深度
    价值：质量基线


---------- A3. LSP 能力补完 —— 5 项 ----------

[08] lsp_rename
    说明：重命名符号 + 所有引用（LSP 最值钱的能力）
    价值：一次改名全工程同步

[09] lsp_format
    说明：按 LSP 服务端格式化（与 format_file 区别是支持项目设置）
    价值：团队风格统一

[10] lsp_code_action
    说明：quick fix（自动修导入缺失 / 类型错误）
    价值：自动修复常见错误

[11] lsp_completion
    说明：自动补全（trigger character 处调）
    价值：LLM 写代码有依据

[12] lsp_signature
    说明：函数签名 + 文档提示
    价值：调 API 不出错


---------- A4. 可观测 / 查询 —— 5 项 ----------

[13] db_query
    说明：只读白名单方式查项目 SQLite（30+ 张表）
    价值：模型能查自己的数据

[14] log_query
    说明：hilog 结构化查询（since/until/priority/keyword）
    价值：排查闭环

[15] trace_export
    说明：导出 trace 为 OpenTelemetry / Jaeger 格式
    价值：跟 TimelinePanel 配套

[16] metric_export
    说明：Prometheus 格式指标导出
    价值：监控对接

[17] log_aggregate
    说明：多源日志聚合（faultlog + hilog + runtime_log）
    价值：单次调用看全貌


---------- A5. API 工作流闭环 —— 4 项 ----------

[18] api_mock
    说明：按 OpenAPI / 鸿蒙 API 自动生成 mock server
    价值：前端不用等后端

[19] api_test
    说明：跑 API 测试用例 + 报告
    价值：API 自动化

[20] api_health
    说明：持续探测外部 API 健康度（不只是 LLM）
    价值：上游故障提前发现

[21] figma_import

---------- B1. 工具输出脱敏（最紧急）—— 1 项 ----------

[57] tools/redact.rs
    说明：所有工具返回前过脱敏正则
         （API key / JWT / Bearer / 邮箱 / 手机号 / 身份证 / 私钥）
    价值：不再泄密到 prompt / DB


---------- B2. 编辑可逆性 —— 2 项 ----------

[58] dry-run 模式
    说明：所有 mutating 工具
         （write_file / edit_file / delete_file / move_file / git_push / deploy）
         支持 dry_run: bool
    价值：不真改，预览效果

[59] 单工具取消 UI
    说明：前端 tool_run 卡片加 abort 按钮
         → abort_tool_call(tool_id)
    价值：不用停整个任务


---------- B3. 工具元数据规范化 —— 4 项 ----------

[60] 副作用标注 lint
    说明：扫 TOOL_SPECS，desc 没"副作用"段报警
    价值：LLM 知道改了什么

[61] desc 长度规范
    说明：200-500 字统一，过长拆到 tool_help
    价值：注意力均匀

[62] task_group 字段
    说明：每工具标 build / fix / explore / deploy / refactor / test 之一
    价值：按任务查找

[63] timeout_hint + cost_hint
    说明：工具元数据补超时和成本字段
    价值：决策更准


---------- B4. 工具可靠性 —— 4 项 ----------

[64] fallback 链
    说明：try_with_fallback(primary, fallbacks) 模式
         （list_emulators 找不到 → list_devices）
    价值：工具永远能返回有用信息

[65] 结构化错误统一
    说明：抽 ToolError { code, category, advice } 替代 Err 字符串
    价值：前端可做错误恢复 UI

[66] tools_health() ping
    说明：启动时跑一遍检查每个域
    价值：HealthPage 仪表盘

[67] 工具响应缓存
    说明：services/tool_cache.rs
         按 (tool_name, project, args_hash) 缓存 10-30s
    价值：高频工具提速 30%


---------- B5. 工具组合 —— 1 项 ----------

[68] 组合工具层

         build_and_deploy / fix_and_retry / scan_and_report / commit_and_push
    价值：LLM 少写 50% prompt


---------- B6. 工具统计 / 排行 —— 1 项 ----------
