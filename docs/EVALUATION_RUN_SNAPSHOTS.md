# 评测运行快照

本文定义 EC-14 的评测运行快照。固定套件 `agent_harmony_fixed_v3` 每次运行除逐场景结果外，还保存 schema v1 的执行上下文与最终证据，用于回答“这次分数是在什么环境、用什么能力得到的”。

## 1. 记录内容

`agent_eval_runs.snapshot_json` 保存以下版本化字段：

| 维度 | 保存内容 | 隐私与真实性边界 |
|---|---|---|
| 模型 | 是否使用、provider、model、协议 | 固定套件不调用模型，因此如实记录 `used=false`，不把默认模型冒充执行模型 |
| 提示词 | profile 版本、SHA-256、是否包含正文 | 固定套件仅记录 `fixed_eval_no_model_v1` 的契约摘要，不保存提示词正文 |
| 工具 | 应用/注册表版本、工具数、规范化注册表 SHA-256、外部调用数 | 摘要覆盖工具名和描述；固定套件不执行外部工具，计数为 0 |
| SDK | 探测状态、来源、默认 API、变体及组件版本、hdc/ohpm/hvigorw 可用性 | 不保存 SDK、IDE、命令行工具的绝对路径 |
| 设备 | 探测状态、连接/授权、型号、系统/API、架构和能力 | 设备 ID 只保存 SHA-256；最多保存 20 台；探测错误脱敏并截断 |
| 资源 | 总耗时、输入/输出 Token、人民币成本、长会话退化指标（压缩次数、事实翻转率、退化预警计数） | 环境探测计入耗时；无模型评测的 Token 与成本均为 0；长会话指标来自固定评测 100 轮压力场景真实执行（EC-19），无真实会话时如实为 0 |
| 证据 | 每个通过/失败用例摘要、最终运行摘要 | 最终 SHA-256 绑定 suite、平台、分数、阈值、逐用例结果和除证据字段外的完整执行快照 |

顶层列 `snapshot_schema_version`、`duration_ms` 和 `evidence_digest` 为检索与兼容提供稳定索引，完整内容以 `snapshot_json` 为准。迁移 `075_eval_execution_snapshots.sql` 给历史运行设置 schema 0 和空快照；读取时使用安全默认值，不伪造历史环境。

## 2. 执行顺序

1. 记录开始时间并自动探测 HarmonyOS SDK/CLI；
2. 通过统一设备命令读取 hdc 设备，失败时保留不可用状态而不改变固定用例结果；
3. 运行版本化固定场景并计算分数；
4. 为逐用例结果和最终运行材料生成 SHA-256；
5. 将结果、快照、耗时和最终摘要原子写入同一条评测记录；
6. 可靠性控制面展示耗时、工具数、SDK、设备数、模型使用状态和最终证据摘要。

设备和 SDK 是本次运行时的环境证据，不等于发布验收。真机未连接、hdc 不可用或 SDK 未发现时，固定的纯内核场景仍可运行，但快照会明确标注 `none` 或 `unavailable`，调用方不能据此声称真机或 SDK 验收通过。

## 3. 演进规则

- 新字段应保持旧 reader 可忽略，破坏性变化必须提升 `schema_version`；
- 模型型评测未来必须填入真实调用的 provider/model/protocol、提示词摘要、Token、成本和外部工具调用数；
- 不得把当前配置、候选模型、推测 API Level或设备别名写成已执行事实；
- 最终证据是完整性摘要，不是签名，也不证明执行环境可信；更强的签名、基线比较和 CI 回退门禁由后续阶段实现。

## 4. 验收

后端测试要求固定评测 100% 通过，并验证：schema v1、模型/Token/成本真实为未使用或 0、逐用例证据数量完整、最终摘要存在、SDK 路径不泄漏且设备 ID 不以明文保存。前端生产构建负责校验快照类型和兼容展示。
