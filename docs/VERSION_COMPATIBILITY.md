# 版本兼容策略

本文定义 `EC-18`：数据库、工作流、Skill、工具协议、知识索引五类核心资产与评测快照/基线两类评测 schema 的统一兼容承诺、破坏性变化流程与当前版本清单。实现入口为 `src-tauri/src/agent/versioning.rs` 的 `asset_versions`。

## 1. 资产与版本策略

| 资产 | 当前版本 | 状态 | 兼容承诺 | 破坏性变化流程 |
|---|---|---|---|---|
| 数据库 | 迁移数（当前 77） | stable | 只允许递增迁移；旧数据必须可前滚且重放受保护 | 新增迁移满足 Q-01：前滚、重复执行保护、兼容旧数据测试；删除或改列必须分步迁移 |
| 工具协议 | `ToolResultV2` schema 2 | stable | 读取器忽略并保留未知字段；新增可选字段使用默认值，可读早期缺字段记录 | 删除字段或改变含义才提升主版本，并提供数据库迁移；历史版本写入 `tool_protocol_versions` |
| Skill 规范 | v1 | stable | manifest 版本化、权限声明与兼容范围按 [Skill 与能力包规范](SKILL_CAPABILITY_SPEC.md) | 旧格式有显式升级路径与内容漂移门禁 |
| 工作流规范 | v1 | stable | 格式、权限差异、审批与版本归档按 [工作流模板规范](WORKFLOW_TEMPLATE_SPEC.md) | 升级与兼容规则见工作流模板规范 |
| 知识索引 | 进程内（无持久 schema） | evolving | 以本机 SDK 声明文件为重建真源，不跨 SDK 版本污染；一旦持久化或跨进程共享必须携带 schema_version | 持久化时先定义 schema 与迁移策略，再落库 |
| 评测运行快照 | schema 1 | stable | 新字段保持旧 reader 可忽略；历史运行按 schema 0 兼容读取 | 破坏性变化提升 schema_version 并保留旧版本读取路径 |
| 评测 CI 基线 | schema 1 | stable | 跨机器比较；套件或结构变化时旧基线自动失效重建 | 套件升级后由下一次 main 运行保存新基线 |

## 2. 统一原则

1. **只增不删**：新增字段、文件、表必须可被旧读取器忽略；删除或改变语义必须提升主版本。
2. **证据先于版本**：版本号本身不证明兼容，兼容由迁移测试、协议测试和旧数据读取测试裁决。
3. **迁移可重放**：数据库迁移必须幂等可重放；恢复、重试、并发启动都不允许重复副作用。
4. **清单可追溯**：`asset_versions` 汇总全部资产版本，发布说明与可靠性面板使用同一数据源，避免文档与实现漂移。

## 3. 验证

- `asset_versions` 单元测试断言：七项资产齐全、数据库版本与迁移注册表一致、工具协议版本与代码常量一致、每个条目都有兼容承诺与迁移说明。
- 数据库迁移注册表测试断言每个迁移可执行且旧数据兼容（见 `db/mod.rs`）。
- 工具协议版本由 `tool_metrics::protocol_versions` 从执行账本反查，新写入与历史记录同时可见。

## 4. 变更流程

任何版本化资产的破坏性变化必须：

1. 提升对应 schema 版本并在本文件更新当前版本；
2. 提供迁移或升级路径（数据库迁移 / Skill 升级器 / 协议转换器）；
3. 添加兼容旧数据的测试；
4. 在 CHANGELOG 的 Unreleased 段记录迁移要点、风险与回滚方式；
5. 发布说明（EC-17）自动汇总上述内容，不得遗漏。
