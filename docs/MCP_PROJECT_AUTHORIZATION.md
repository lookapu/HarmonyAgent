# MCP 项目授权与作用域

本规范定义 EC09 的 MCP 安全边界。MCP 是外部进程和动态工具来源，服务器返回的工具名、描述或 schema 都不能自行获得 HarmonyAgent 权限。

## 默认失败关闭

迁移 `071_mcp_project_authorization.sql` 为每个服务器增加授权状态、工具白名单、目录白名单、网络策略和凭据变量白名单。升级前已有配置保持 `unconfigured`：仍可在 MCP 页面查看和测试，但不会启动为 Agent 长驻连接，也不会注入工具清单。

全局 MCP 只作为可复用配置模板，不再自动进入每个项目。要在 Agent 中使用，先把全局配置克隆到目标项目，再完成该项目的授权。项目 A 的实例不会被项目 B 枚举、连接或路由。

## 授权字段

| 字段 | 规则 |
| --- | --- |
| `allowed_tools` | 至少一个精确工具名；禁止 `*`、空白和 MCP 协议分隔符 |
| `allowed_roots` | 至少一个无 `..` 的项目相对目录；`.` 表示项目根 |
| `network_policy` | `deny` 或 `allow`；缺省 `deny` |
| `credential_keys` | 允许传给子进程的环境变量名（包括普通配置与凭据）；不记录或展示变量值 |

连接成功后只把 `allowed_tools` 与服务器实际 `tools/list` 的交集注入 Agent。调用时再从数据库重新定位当前项目实例，复验启用状态、授权状态和工具名，提示词中曾出现过的旧工具不能绕过门禁。

MCP 页面的“测试连接”是用户显式诊断：它清空宿主应用继承环境，但会临时使用该配置自己保存的 env 和网络完成握手、列出工具，便于授权前选择精确工具名。测试成功不会创建 Agent 授权或长驻连接。

## 目录、网络与凭据

- MCP 子进程工作目录固定为项目当前工作树根；路径、文件、目录、root、cwd、workspace 等参数会规范化后检查是否位于 `allowed_roots`。
- `network_policy=deny` 时拒绝网络语义工具及 URL/endpoint/host 等网络参数，不注入系统代理，强制 npx 使用离线模式，并向子进程传入明确的拒绝策略标记；`allow` 仍只代表该项目允许此 MCP 使用网络，不改变工具白名单。
- 子进程不再继承桌面应用的完整环境。只保留启动运行时所需的最小系统变量；服务器配置中的任何环境变量都只有出现在 `credential_keys` 时才会传入，未列出的普通配置和凭据一律不传。
- 命令参数中内嵌 token、password、API key 或带用户信息的 URL 会阻止授权；凭据必须转移到环境变量并单独列入项目白名单。
- MCP 返回、错误、工具审计和 UI 摘要继续走统一脱敏；服务器卡片只显示环境变量名，不显示值。

更新命令或环境变量会立即把授权重置为 `unconfigured` 并断开旧连接；修改授权、禁用或删除服务器也会回收缓存子进程。授权变更写入 `agent_audit_events`，只记录作用域和白名单，不记录凭据值。

## 执行边界

EC09 提供 HarmonyAgent 调用层的最小授权：工具不暴露、参数不放行、环境不继承、项目不串线。第三方 MCP 进程仍是外部代码；操作系统级文件沙箱、强制网络隔离、来源签名、速率限制和进程故障域属于 EC10。因而不应把 `network_policy=deny` 解释为系统防火墙，也不应授权不可信的 MCP 可执行文件。

## 回归要求

- 旧配置迁移后不能被 Agent 查到；
- 全局配置不能在项目中直接路由；
- 未授权、跨项目、未列入工具、越界路径和 deny 网络参数全部失败；
- 连接配置变化后旧授权和旧进程立即失效；
- 敏感环境变量未列入白名单时不传给子进程；
- 一台 MCP 失败或超时不影响其他服务器与主对话流程。
