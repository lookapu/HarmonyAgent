# HarmonyAgent 持续演进任务路线图

> 状态：执行中  
> 适用范围：长会话、Agent 工具链、HarmonyOS 开发闭环、生态集成与质量体系  
> 更新规则：任务完成时同步勾选本文件，并在 `CHANGELOG.md` 记录用户可感知变化；数据库结构只能通过递增迁移演进。

长会话数据映射与事实优先级见 [CONTEXT_V2.md](CONTEXT_V2.md)。

## 1. 目标与推进原则

下一阶段的目标不是继续堆叠工具数量，而是让 HarmonyAgent 成为能够长期协作、稳定执行、理解鸿蒙工程并完成真机验证的工程伙伴。

推进顺序如下：

1. 长会话执行内核 V2：保证任务在上下文压缩、应用重启和目标变化后仍可继续。
2. Agent 工具链质量工程：统一契约、减少误调用、强化验证和恢复。
3. HarmonyOS 开发闭环：打通工程理解、构建、部署、运行和诊断。
4. 生态集成与产品化：连接 SDK、ohpm、开源生态和团队工作流。

所有阶段共同遵守以下原则：

- 完成必须由工具证据和目标契约裁决，不能只依赖模型自述。
- 文件、构建、测试、设备、Git 和外部系统状态保存为结构化事实，摘要只承担导航作用。
- 副作用操作必须可识别、可审批、可恢复；无法安全重放时必须先验证外部状态。
- 优先改善已有 201 个工具的成功率和组合能力，再增加新工具。
- 每个里程碑必须同时交付实现、迁移、测试、文档、指标和故障恢复验证。
- 不以消除全部历史告警作为单个功能的前置条件，但不允许新增告警或扩大技术债。

## 2. 当前基线

项目已经具备本路线图所需的底座：

- Durable Run、执行步骤、检查点、目标契约和结构化工具结果。
- 持久队列、DAG、多 Worker 租约、fencing 和崩溃恢复。
- 工具专用 OS 线程、panic 隔离、副作用 prepared/committed 状态和卡死指标。
- SQLite 会话、消息、快照、记忆、知识库和运行事件。
- HarmonyOS 工程识别、Hvigor/OHPM、HDC、HAP 部署、Hilog、LSP 和 API 知识能力。
- 可靠性控制面、SLO、故障场景评测及 Worker/工具崩溃 E2E 门禁。

本路线图在这些能力上增量演进，不另建一套平行运行时。

## 3. 阶段一：长会话执行内核 V2

### 3.1 分层上下文

- [x] `LC-01` 定义统一的 `ConversationContextV2`，拆分当前窗口、任务状态、项目记忆和历史归档。
- [x] `LC-02` 为上下文条目增加来源、时间、作用域、可信度、版本和失效条件。
- [x] `LC-03` 将最近消息、当前错误、活跃文件和待审批事项组成有限大小的热上下文。
- [x] `LC-04` 将目标、计划、验收条件、已完成项、阻塞项和下一步保存为结构化任务快照。
- [x] `LC-05` 按项目保存架构约定、构建命令、模块职责、用户偏好和已确认决策。
- [x] `LC-06` 历史工具输出改为产物引用和摘要，原始内容保留在可回溯存储中。
- [x] `LC-07` 为项目切换、分支切换、文件变更和设备变化实现记忆失效策略。

### 3.2 摘要与事实保持

- [x] `LC-08` 建立增量摘要流程，避免每轮重新总结完整会话。
- [x] `LC-09` 摘要前后执行事实对账，覆盖文件修改、测试结果、构建产物、Git 状态和设备状态。
- [x] `LC-10` 摘要不得覆盖未完成任务、用户约束、审批等待和失败原因。
- [x] `LC-11` 记录摘要版本及其覆盖的消息游标，支持定位和重建。
- [x] `LC-12` 当结构化事实与自然语言摘要冲突时，以可验证事实为准并生成纠偏事件。

### 3.3 恢复、分支与目标变更

- [x] `LC-13` 应用重启后从 Durable Run、任务快照和事件游标恢复当前任务。
- [x] `LC-14` 恢复前验证工作区、进程、构建产物、设备和远端 Git 状态，禁止盲目重放副作用。
- [x] `LC-15` 支持暂停、继续、取消、重试和从最近安全检查点恢复。
- [x] `LC-16` 用户修改目标时生成契约差异，取消不再适用的步骤并重新计算验收条件。
- [x] `LC-17` 支持从消息、检查点、构建失败或 Git 提交创建会话分支。
- [x] `LC-18` 分支合并只合并结构化决策、产物和验证证据，不直接拼接完整上下文。
- [x] `LC-19` 子 Agent 以任务契约、限定上下文和结构化结果与主任务通信。

### 3.4 长会话产品体验

- [x] `LC-20` 在 Workspace 展示当前目标、阶段、上下文预算、摘要次数和恢复点。
- [x] `LC-21` 提供“为什么记住”“为什么遗忘”“事实来源”和“重新载入历史”的解释入口。
- [x] `LC-22` 让用户能够固定关键消息、决策、文件和验收条件。
- [x] `LC-23` 对上下文即将压缩、目标发生冲突和恢复验证失败提供明确提示。

### 3.5 阶段验收

- [x] 100 轮以上会话后仍能准确给出目标、已完成项、阻塞项和下一步。
- [x] 连续执行数小时，应用重启后能从安全检查点继续。
- [x] 上下文压缩后，文件修改、测试结果、未提交状态和用户约束保持准确。
- [x] 用户中途改变目标后，不再执行旧契约中的危险或无关步骤。
- [x] 崩溃恢复不重复部署、提交、推送、删除或外部写入。
- [x] 可从关键结论追溯到消息、文件、工具结果或外部状态证据。

## 4. 阶段二：Agent 工具链质量工程

### 4.1 统一工具契约

- [x] `TC-01` 为全部工具统一 `ToolResultV2` 字段：状态、修改、产物、验证、恢复、建议和错误信封。
- [x] `TC-02` 为工具补齐副作用等级、幂等能力、超时、取消、重试和审批元数据。
- [x] `TC-03` 将长输出保存为产物，模型上下文只接收有界摘要和引用。
- [x] `TC-04` 统一敏感信息脱敏规则，覆盖 token、证书、签名材料、环境变量和设备标识。
- [x] `TC-05` 区分成功、部分成功、验证失败、等待审批、可重试失败和永久失败。
- [x] `TC-06` 工具声明结果验证器；副作用工具声明补偿或人工恢复指引。

### 4.2 能力包与工具选择

- [x] `TC-07` 建立项目理解、编译修复、功能开发、重构、构建部署、设备诊断、Git 交付等能力包。
- [x] `TC-08` 每个能力包定义最小工具集合、推荐顺序、停止条件和验收条件。
- [x] `TC-09` 根据任务阶段动态裁剪工具描述，避免每轮向模型暴露全部工具。
- [x] `TC-10` 检测功能重复、长期未使用和高失败率工具，形成合并、隐藏或修复清单。
- [x] `TC-11` 为参数错误提供 schema 级纠错建议，但不自动修正敏感参数。
- [x] `TC-12` 工具选择器结合历史成功率、预计成本、耗时、副作用和当前环境排序。

### 4.3 执行与验证闭环

- [x] `TC-13` 固化“理解目标 → 可验证计划 → 最小工具集 → 执行 → 验证 → 验收”循环。
- [x] `TC-14` 文件修改后自动选择格式化、静态检查、测试或构建验证，避免只有写入证据。
- [x] `TC-15` 部署、Git 和外部写入完成后读取真实状态确认结果。
- [x] `TC-16` 多步工具流支持事务边界、检查点、补偿动作和失败后降级方案。
- [x] `TC-17` 对卡死线程、孤儿进程、输出洪泛和不可取消调用增加隔离测试。
- [x] `TC-18` 将人工审批作为可恢复状态，重启后仍能继续等待或安全取消。

### 4.4 指标与治理

- [x] `TC-19` 采集工具成功率、参数错误率、超时率、重试率、取消延迟和平均耗时。
- [x] `TC-20` 采集工具对最终任务完成的贡献度，区分“调用成功”和“目标推进”。
- [x] `TC-21` 为副作用重复率、错误工具选择率和无效调用率设置 SLO。
- [x] `TC-22` 可靠性面板支持按工具、能力包、模型、项目和版本比较。
- [x] `TC-23` 每次工具协议变更提供兼容迁移或明确的版本边界。

### 4.5 阶段验收

- [x] 所有已注册工具均有完整元数据和结构化结果，未知字段可向后兼容。
- [x] 高频工具具备成功、失败、超时、取消、重试和恢复测试。
- [x] 典型任务暴露给模型的工具数量明显下降，完成率不降低。
- [x] 副作用重复执行率可度量，并在崩溃评测中保持为零。
- [x] 工具调用失败时，用户能看到原因、影响、已完成部分和可执行下一步。

## 8. 核心指标

| 维度 | 指标 | 目标方向 |
|---|---|---|
| 任务 | 最终任务完成率、一次完成率、人工介入次数 | 完成率上升、介入下降 |
| 长会话 | 事实保持率、恢复成功率、错误继续率 | 保持与恢复上升，错误继续下降 |
| 工具 | 参数错误率、无效调用率、超时率、重复副作用率 | 持续下降，重复副作用接近零 |
| 鸿蒙 | 构建修复率、真机部署成功率、诊断命中率 | 持续上升 |
| 效率 | 完成耗时、Token、成本、工具调用次数 | 在完成质量不下降时降低 |
| 体验 | 用户取消率、重复说明次数、恢复后确认次数 | 持续下降 |

指标必须按版本、模型、项目类型和任务场景分组，避免平均值掩盖严重回退。

## 9. 推荐里程碑

### M1：长会话事实底座

- 范围：`LC-01` 至 `LC-12`、`Q-01` 至 `Q-05`。
- 交付：上下文 V2、任务快照、增量摘要、事实对账、迁移和回归测试。
- 出口：100 轮会话压缩后，关键事实保持测试通过。

- 出口：重启及崩溃场景中无重复副作用，用户可追溯恢复依据。

### M3：工具链质量闭环

- 范围：`TC-01` 至 `TC-23`。
- 交付：工具契约、能力包、动态裁剪、指标和完整失败体验。
- 出口：高频工具故障矩阵通过，典型任务的工具暴露量和无效调用显著下降。

- 交付：多设备状态、部署、启动、日志、崩溃、UI 与性能验证。
- 出口：至少一套真机端到端故障修复场景稳定通过。

- 出口：第三方集成可审计，发布具有可重复的质量证据。

## 10. 每个任务的完成定义

任务只有同时满足以下条件才能勾选：

1. 实现已接入真实用户路径，不是未调用的孤立模块。
2. 数据结构有迁移与兼容策略，副作用有恢复策略。
3. 单元、集成或 E2E 测试覆盖成功路径和关键失败路径。
4. 产生可观测指标、结构化日志或审计事件。
5. 用户可感知行为已更新 README、架构文档或专题文档。
6. 前端测试、Lint、构建和相关 Rust 测试通过；新增告警为零。
7. 验收证据可从 Run、步骤、工具结果、产物或外部状态追溯。
