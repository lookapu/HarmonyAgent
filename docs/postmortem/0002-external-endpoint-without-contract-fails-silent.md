# 依赖非契约外部端点，端点下线后整条链路静默空跑

> 证据：`CHANGELOG.md` → `## Unreleased` → **修复：华为文档站下线 `.md` 端点后，
> API 知识库整体失效**。
> 「为什么没被立刻发现」一节为据现有材料重建，缺证据处标 `待补`，未补前不作为定论。

## 现象

版本 diff 与 API 参考正文两条链路同时失效：取不到正文。
华为文档站已下线"页面 URL 追加 `.md` 返回 Markdown"这个端点，全站返回 404。

链路是**空跑**而不是报错——没有异常、没有告警，只是结果为空。

## 机制

原实现把「页面 URL + `.md`」当作取正文的正规途径。这是文档站的一个便利端点，
不是它的对外契约：没有版本承诺、没有弃用周期、**随时可以单方面下线**。

链路对 404 的处理是"没拿到就是没有"，于是：

- 端点存在时：一切正常，端点看起来是**设计的一部分**而非临时手段
- 端点消失时：正常返回空 → 继续往下走 → 最终产出空知识库

两类失败被同一个 `Option`/空值表达，**"没抓到"和"本来就没有"不可区分**。

## 复发模式

**凡是把"外部服务当前恰好提供的非契约端点/便利接口"写进数据链路，
就必须同时具备两件事：**

1. 端点不可用时**显式失败**，不许降级成"结果为空"
2. 定期的真实内容断言（不是请求成功断言）——断言"这一页确实抓到了正文"，
   而不是"这个 URL 返回了 200"

请求成功 ≠ 内容正确，这是外部数据链路的通用失效模式。

## 钉住了什么

- 改用文档站自身的 `documentPortal/getDocumentById` 接口取正文，
  配套新增 HTML 锚点/表格提取与 HTML→Markdown 转换
- 版本清单入口从"猜 URL 形态"改为**按内容下钻**：`apidiff-2600` 只列 release/beta
  子入口，再逐层收集 Kit diff 页（最多 3 层）——不再依赖某个拼接出来的地址规则
- 兜底 slug **逐条按线上实际 objectId 校正**（13 个 camelCase slug 已 404），
  写进了代码而不是注释
- 覆盖度变成可量化的断言：参考正文从 310 页 → 681 页，
  模块级未命中降到 25 个，且**逐个经搜索确认**确无专属参考页
- 同一批次还修了两个下游回归：兜底 slug 表里 `@ohos.preferences` /
  `@ohos.relationalStore` 两个陈旧别名先占位，导致 `api_details.slug` 唯一约束下
  真名显示"未命中"——**别名表与真名表共享唯一约束时，别名先到会挤掉真名**

## 对本项目的推广

本项目有三条同构的外部依赖面：

| 依赖 | 非契约风险 |
|---|---|
| 华为文档站 / `getCatalogTree` | 端点、字段名、目录结构都可能变 |
| ohpm 包市场（`ohpm_search` / `ohpm_recommend`） | 索引格式、热度口径 |
| 第三方 MCP server 的 instructions | 服务方自由文本，且直接进 system prompt |

统一的自查问题：**这条链路"成功"的时候，我断言的是请求成功还是内容真实？**

对 ohpm 与 MCP 这两处，本项目目前的断言强度尚未核过——
与本篇同类的空跑风险可能仍然存在。（未验证，记为待查，不作结论。）
