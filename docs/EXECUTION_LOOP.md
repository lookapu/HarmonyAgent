# 统一执行循环

执行型任务统一遵循以下循环：

1. 理解目标：从目标契约和来源证据确认范围、约束与真实状态。
2. 可验证计划：把目标契约中的必需项作为计划骨架，可用 `plan_task` / `todo_write` 细化。
3. 最小工具集：结合能力包、当前阶段和运行期排名，只暴露当前阶段需要的工具。
4. 执行：真实工具调用进入持久步骤和工具审计，失败不会伪装成完成。
5. 验证：写入或破坏性副作用之后必须出现独立验证证据。
6. 验收：运行内核按目标契约裁决；缺项自动进入补救轮。

状态机阶段为 `understand`、`plan`、`select`、`execute`、`verify` 和 `accept`。每次阶段变化都写入 Durable Run 的 `workflow.stage` 事件，载荷包含计划、最小工具集、当前证据、阻塞项和验收报告。应用或会话恢复后可以从真实步骤与工具轨迹重新推导，不依赖模型记忆。

状态机是现有 Coordinator、Tool Worker、能力包与 Acceptance Engine 的统一控制视图，不重复实现工具执行。阶段提示每轮注入，最终完成仍由 Acceptance Engine 决定。
